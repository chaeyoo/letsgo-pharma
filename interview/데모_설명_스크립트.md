## 2. 2~3분 상세 버전 — 이 순서로 말한다

### 2.1 문제 정의부터 (도메인 이해 어필)

"RA·PV 담당자는 규제문서의 바다에서 일합니다. 답은 고시나 SOP 어딘가에 있지만
찾는 데 시간이 걸리고, 틀리면 곧 컴플라이언스 사고입니다. 그리고 허가가 끝이 아니라,
시판 후에는 이상사례 접수→중대성 판정→보고기한 계산→당국 보고라는 PV 케이스 처리가
기다립니다. 이 두 반복업무를 근거 기반으로 자동화하는 게 목표였습니다."

### 2.2 무엇을 하는가 (데모 시나리오 2~3개)

- "'신약 품목허가 심사 며칠 걸려?' → RAG가 규제문서에서 근거를 찾아 출처와 함께 답합니다."
- "'복용 후 아나필락시스로 입원했어요, 언제까지 보고?' → `assess_adverse_event` 도구가
  중대성 판정 + 기한 계산 + WHO-UMC 인과성 제안까지 처리하고, 판정 근거 규정(REG-005)을
  RAG로 중첩 검색해 결과에 부착합니다."
- "복합 질문이면 에이전트가 검색·체크리스트·마감일 도구를 스스로 조합합니다 —
  이게 Agentic Workflow입니다."

### 2.3 아키텍처 핵심 한 가지만 꼽으라면 — 모델과 도구의 MCP 분리

**말하기 4박자** (분리 선언 → 규격 깊이 → 분리의 증명 → 확장성):

> ① "핵심은 **모델과 도구의 분리**입니다. 에이전트 코드에 RA·PV 도구 코드를 직접
> 넣는 게 아니라, 도구는 **별도의 MCP 서버로 분리**하고 **표준 규격으로 연결**했습니다."
> ② "MCP가 정의하는 기본 기능은 Tool·Resource·Prompt **세 가지**인데, FastMCP 서버에
> **이 셋을 전부 구현했습니다** — 업무 도구 6개, 규제문서 원문을 열람하는
> Resource(`regulation://{doc_id}`), 케이스 접수 SOP를 배포하는 Prompt(`pv_case_intake`)입니다."
> ③ "MCP 서버는 **별도 프로세스**라, 우리 에이전트도 Claude Desktop 같은 외부
> 클라이언트도 **같은 서버에 원격으로 붙습니다.** 공개 URL에 Bearer 인증을 붙여
> 배포까지 해놔서 이 장면을 바로 시연할 수 있습니다."
> ④ "새 사내 시스템은 **도구로 추가만 하면 됩니다** — Hey.GC 2.0이 말하는 확장성
> 원리를 소규모로 그대로 구현한 것입니다."

③이 이 층의 심장 — "우리 에이전트나 Claude Desktop이나 똑같은 클라이언트"라는 한
문장이 곧 모델↔도구 분리가 진짜(네트워크 경계)라는 증명이다. 분리가 가짜(인메모리)면
외부 클라이언트가 붙을 수 없다.

**꼬리질문 카드** (말하기에서 뺀 디테일 — 물어보면 꺼낸다):

- "primitive가 뭔가요?" → MCP 명세가 정의하는 서버 제공 **기능(feature)** 세 종류.
  primitive = 체계가 제공하는 기본 요소(빌딩 블록)라는 CS 관용어 — 언어의 primitive
  type(int·bool), 그래픽스의 점·선·삼각형과 같은 용법. 핵심은 셋의 **주도권이 다르다**:
  - **Tool** (model-controlled) — **모델이** 스스로 판단해 호출하는 실행 함수.
    LLM이 도구의 이름·docstring·타입힌트(스키마)를 보고 언제 쓸지 결정한다.
    검색·계산·판정처럼 '행동'이 필요할 때. 이 프로젝트: `search_regulations`,
    `assess_adverse_event` 등 6종.
  - **Resource** (application-controlled) — **앱/클라이언트가** URI로 읽어 컨텍스트에
    첨부하는 데이터. 실행이 아니라 '열람'이고, 부르는 주체가 모델이 아니라 클라이언트.
    이 프로젝트: `regulation://{doc_id}` — 규제문서 원문 열람.
  - **Prompt** (user-controlled) — **사용자가** 명시적으로 선택하는 재사용 프롬프트
    템플릿(슬래시커맨드처럼). 이 프로젝트: `pv_case_intake` — 케이스 접수 SOP를
    표준 템플릿으로 배포. "조직의 업무 절차를 프롬프트로 표준화"라는 발상이라
    사내 시스템 통합(Hey.GC) 문맥과 바로 연결된다.

  실체는 JSON-RPC 메서드 묶음(`tools/list·call`, `resources/list·read`,
  `prompts/list·get`)이고, 초기화 핸드셰이크의 capability 협상으로 서로 알린다 —
  preflight의 '도구 6종 노출 확인'이 바로 `tools/list` 호출. 대부분의 MCP 서버는
  Tool만 쓰는데(사실상 Function Calling 래퍼), 셋을 용도대로 다 쓴 게 규격 이해의 증명.
- "구체적으로 어떻게 연결되나요?" → streamable HTTP transport, 에이전트·API 가
  `MCP_SERVER_URL` 환경변수로 원격 연결(`_mcp_client()` 헬퍼가 Bearer 토큰 자동 부착).
  외부 클라이언트는 공개 URL + `MCP_AUTH_TOKEN`(Claude Desktop 은 `mcp-remote`
  프록시 경유 — 3.5 배포 참고).

### 2.4 신뢰성 설계 (규제 도메인에서 차별화되는 부분)

- "중대성 판정이나 보고기한처럼 **규정이 정해둔 계산은 LLM에게 맡기지 않고,
  결정론적 규칙 코드**가 처리합니다. LLM은 어떤 도구를 쓸지 조율만 하고요.
  감사와 재현이 필수인 도메인이라, 같은 입력에는 항상 같은 답이 나와야 하기
  때문입니다."
- "개인정보는 **두 겹**으로 막습니다. 에이전트 입구에서 먼저 마스킹해서 LLM API·
  검색·로그 어디에도 원문이 흘러가지 않게 하고, MCP 도구 계층에서 한 번 더
  마스킹합니다. 두 번째 겹이 필요한 이유는, 에이전트를 거치지 않고 Claude Desktop
  같은 외부 클라이언트가 도구를 직접 부르는 경로도 있기 때문입니다(심층방어)."
- "답변이 나가기 전에는 **전부 사후 검증 게이트**를 거칩니다. 답변 속 수치·단위·
  날짜·방향 표현을 실제 근거 — 검색 결과와 도구 출력 — 와 대조하고, 이때 사용자가
  질문에 쓴 표현이 근거로 둔갑하지 않도록 **입력에서 온 문구는 근거에서 뺍니다.**
  대조에 실패해도 답변을 차단하는 게 아니라 경고를 붙입니다 — 최종 확정은 사람
  몫이기 때문입니다."
- "서버가 뜨기 전에는 **preflight 자가 점검**이 돕니다. 설정이 모순되지 않는지,
  문서 코퍼스가 온전한지, 방금 말씀드린 검증 게이트가 제대로 작동하는지까지 27건을
  스스로 테스트해서, 하나라도 실패하면 기동 자체를 막습니다. **안전장치가 고장난
  채 배포되는 것은 안전장치가 없는 것보다 나쁘다**는 원칙입니다."

### 2.5 평가와 정직성

"벡터 검색만 썼을 때는 Hit@1이 0.938이었는데(밀집임베딩 e5 기준 — 어휘 TF-IDF
시절엔 0.875였고, 임베딩 교체만으로 하드네거티브 축이 0.786에서 1.000까지 올랐습니다),
하이브리드 검색에 리랭킹, 질의확장까지 붙여서 1.000까지 끌어올렸습니다.
다만 이 1.000은 좀 걸러 들으셔야 합니다 — 그
32문항은 제가 오류 분석하면서 계속 들여다보고 고친 개발셋이거든요. 계속 보고 고친
문제는 결국 다 맞히게 되니까요(개발셋 포화). 물론 고친 건 문항별 짜맞추기가 아니라
검색 메커니즘입니다 — 동의어를 못 잡길래 질의확장을 넣고, 정확한 용어 질의가
밀리길래 BM25를 섞고, 순위가 아쉬워서 리랭킹 신호를 더한 식이라, 같은 개선이 안 본
문제에서도 통합니다. 그 증거로 진짜 성능은 튜닝에 한 번도 안 쓴
홀드아웃 6문항으로 따로 확인하는데, 여기서도 만점이었습니다. 다만 **6문항 만점으로
할 수 있는 말은 많지 않아서**, 수치에는 항상 신뢰구간을 붙입니다(Wilson 하한 0.61) —
습관이 아니라 CI에 박아놔서, 어기면 빌드가 깨집니다."

> 한 줄 압축: **"1.000은 완벽이 아니라, 이 표본에서 실패 관측 0."**
> 기억 앵커 3단어: **올렸다(0.938→1.000) → 문제집(개발셋 포화) → 모의고사(홀드아웃+구간)**

**꼬리질문 카드:**

- "하한 0.61이면 너무 낮은 것 아닌가요?" → "맞습니다. 6문항으로는 그 이상을 주장할
  수 없어서, 그 이상을 주장하지 않는 겁니다. 지금 수치로 말할 수 있는 건 '이 표본에서
  실패 관측 0'까지고요. 구간을 좁히는 방법은 튜닝이 아니라 **문항을 늘리는 것**뿐이라,
  실데이터를 반입하면 평가셋 확장이 첫 작업입니다." — 구간 폭은 성능이 아니라
  **증거의 양**의 성적표다: 만점 기준 하한이 6문항 0.61 → 10문항 0.72 → 30문항 0.89 →
  100문항 0.96. 낮은 하한을 먼저 꺼내는 것 자체가 "수치로 거짓말 안 한다"는 신호 —
  규제 도메인에서 그게 곧 신뢰다.
- "홀드아웃이 왜 6개뿐인가요?" → 데모 코퍼스가 13문서라 서로 독립적인 문항을 뽑는
  데 한계가 있다. 그 트레이드오프를 알고 '적은 문항 + 구간 병기'로 정직하게 갔다.
  홀드아웃 규율(실패 시 처리 절차 포함)은 `eval/holdout_dataset.json` 파일 주석에
  박아뒀다 — 말이 아니라 아티팩트로 보여줄 수 있다.
- "preflight 돌 때마다 홀드아웃도 검사하나요?" → 아니다, 역할이 다르다.
  preflight 의 스모크는 **canary**('어려운' 케이스가 아니라 '무조건 되어야 하는'
  케이스) — 기동할 때마다 "이 환경에서 뜰 자격이 있나"(데이터·설정·안전장치 무결성)를
  묻고 실패 시 기동 차단. 홀드아웃 평가는 CI 의 평가 스텝 — 코드가 바뀔 때마다
  "이 변경이 품질을 깨뜨렸나"를 묻고 실패 시 머지 차단. 코드·데이터가 같으면 검색은
  결정론이라 기동 시점에 품질이 변할 수 없다 — 품질 검사는 코드 변경 시점(CI)에
  있는 게 맞다. **canary 는 가용성 신호, 홀드아웃은 품질 신호.**
- "HardNegHit@1은 뭔가요?" → **하드네거티브** = 코퍼스 13종에 일부러 넣은 '비슷해
  보이는 오답 문서' 6종(의료기기 허가·화장품 표시광고·의약외품 신고 등 — 어휘는
  겹치지만 도메인이 다른 문서). 개발셋 32문항 중 **14문항이 이를 겨냥한 함정 문제**고,
  그 부분 점수가 HardNegHit@1(`1.000 [0.785, 1.000]`, n=14) — "의약품 질문에 의료기기
  문서로 낚이지 않는가", 즉 검색기의 **분별력**을 따로 재는 지표다. 쉬운 문항 점수에
  함정 문항 성적이 희석되지 않게 분리해서 본다.
- "ContextRecall은 뭔가요?" → Hit@1이 '정답 **문서**를 1위로 뽑았나'라면,
  ContextRecall은 '답을 쓰는 데 필요한 **관련 청크**가 검색 결과 안에 회수됐나'다.
  문서는 맞았는데 정작 필요한 조항 청크가 빠지면 답변이 부실해지므로, RAG 는 두
  지표를 같이 본다 — 문서 단위 정확도와 근거 단위 회수율의 분리.

### 2.6 마무리 — 왜 이게 FDE 증명인가

"솔직히 말씀드리면, 이 데모는 제가 저 자신에게 던진 질문에서 시작했습니다 —
**'나는 FDE 역할을 실제로 해낼 수 있는 사람인가?'** 그 답을 말로 준비하는 대신,
만들어서 확인하고 싶었습니다. 그래서 FDE가 하는 일을 그대로 해봤습니다: 현업 문제를
도메인 언어로 정의하고, 배포 가능한 형태로 만들고 — 원커맨드 실행, 오프라인 폴백,
preflight, 관측 계기판까지 — 수치로 검증하고 그 한계까지 정직하게 문서화했습니다.
규제 수치는 데모용 샘플이고, 증명하려던 건 규제 자문이 아니라 **이 일하는 방식
자체**입니다. 이 과정을 끝내고 나니 '할 수 있을까'가 **'해봤다'**로 바뀌었습니다 —
그게 이 데모의 가장 큰 수확입니다."

> 구조: 의심(한 문장) → 행동("만들어서 확인") → 증거(4박자 목록) → 안전핀(샘플 데이터)
> → 확신("할 수 있을까 → 해봤다"). **의심 헤지는 여기서 한 번만** — 발표 중간에
> "부족하지만"류 헤지가 반복되면 이 마무리의 힘이 빠진다.

## 3. "코드 수준으로 설명해보라" 대비 — 서브시스템별 카드

면접관이 파고들면 아래 카드에서 꺼낸다. 전부 실제 구현 확인 완료(파일:라인).

### 3.1 RAG 파이프라인 (`src/rag/`)

- **청킹**: 마크다운 헤딩 경계 1차 분할 + 슬라이딩 윈도우 2차 분할, `CHUNK_SIZE=500` /
  `CHUNK_OVERLAP=80` (`src/config.py:31-32`). 각 청크 앞에 `[문서제목 > 섹션]` 컨텍스트
  prefix를 붙여 임베딩·BM25·리랭커에 모두 싣는다(`chunker.py:97`) — Contextual Retrieval
  경량판.
- **임베딩**: `EmbeddingProvider`를 상속이 아닌 `Protocol`(구조적 타이핑)로 정의
  (`embedder.py:24-28`). 구현체 4종 실존 — **SentenceTransformerEmbedder(기본,
  multilingual-e5-small 밀집임베딩, query:/passage: 비대칭 prefix를 임베더 내부에서 처리)**,
  TF-IDF(augmented TF + L2 정규화 — ML 미설치 환경 자동 폴백), HashingEmbedder(signed
  feature hashing, blake2b 안정 해시), **VoyageEmbedder(실제 상용 API 경로, urllib만으로
  REST)**. 기본값 `EMBEDDER_KIND=auto`가 dense→tfidf 자동 폴백을 담당하고 preflight가
  실제 잡힌 provider를 리포트. "pluggable이라고 말만 한 게 아니라 로컬 밀집·상용 교체
  경로까지 구현"이 어필 포인트.
- **하이브리드**: Okapi BM25(k1=1.5, b=0.75) + 밀집임베딩(e5) 코사인(폴백 TF-IDF),
  `score = α·vec + (1-α)·bm25`, `HYBRID_ALPHA=0.4` (dense 전환 후 재스윕 — 0.5는 의미
  인접 이웃 문서 1건 역전, `retriever.py:254`). min-max 정규화는 **버전 필터 통과 후보군
  안에서만** 수행해 스케일 왜곡 방지. 원점수 무신호면 빈 결과를 반환하는 **무신호
  계약** — 밀집 코사인은 무관 질의에도 0이 안 나와서 provider별 바닥값(`DENSE_SIGNAL_FLOOR`
  =0.835, 실질의 vs 무관질의 분포 실측)으로 일반화했다(`retriever.py`).
- **리랭커 v3 = 4신호 가중합 + 섹션 타입 prior** (`retriever.py:288-386`):
  coverage 0.55 / phrase 0.20 / section 0.15 / title 0.10. 여기에 질의 의도로 게이트되는
  구조 신호 — 대조 섹션("X와의 차이") penalty 0.3은 질의에 비교 마커가 **없을 때만**,
  서두(목적·개요) penalty 0.055는 정의형 질의가 **아닐 때만** 발동. "잔여 하드네거티브
  실패는 4신호의 어떤 재가중으로도 안 뒤집혀서 재가중이 아니라 **신호 추가**로 풀었다"가
  핵심 서사.
- **rerank_weight=0.9 블렌딩**: 순수 재정렬(1.0)은 쉬운 질의를 오히려 떨어뜨려 1차
  하이브리드 점수를 10% 섞는다 — Cross-Encoder가 first-stage 점수와 결합하는 실무 관행.
- **질의확장**: 단방향(구어→정식 용어) 동의어 사전, append 방식이라 원 질의 신호 보존.
  1단계 회수엔 전 가중, 2단계 리랭커에선 확장 토큰만 **절반 가중**. 최장 일치 우선으로
  "라벨링" 안의 "라벨" 오발화 차단.
- **버전 인지 검색**: `as_of` 미지정 = 오늘과 동치로 통일. 폐지본은 "당시 시행 중이던
  구간 `[시행일, 후속본 시행일)`"이면 포함 — 무조건 제외하면 과거 시점 조회에서 신·구판이
  모두 걸러지는 논리 결함을 방지(`retriever.py:213-216`). 시행일 미상 문서는 **fail-closed**
  로 제외하되 크래시 대신 preflight가 데이터 결함을 보고.
- **스윕 6축**(`eval/sweep.py`): rerank_weight·alpha·idf_power·aux ablation·섹션 prior·
  청킹 size×overlap. "TF-IDF 시절 alpha는 둔감해 중립값 0.5였는데, 밀집임베딩 전환 후
  재스윕에서 0.5가 이웃 문서 1건을 역전시켜 0.4로 조정 — 감이 아니라 스윕으로 정했고,
  임베더가 바뀌면 다시 쟀다. idf_power는 여전히 둔감이라 안 건드렸다."

### 3.2 에이전트 · MCP · API (`src/agent/`, `src/mcp_server/`, `src/api/`)

- **단일 진입점** `RaAgent.chat()`: 최상단에서 무조건 `redact()` → 이후 3갈래 분기
  (LLM direct / PydanticAI / 오프라인 폴백). 마스킹이 분기보다 먼저라 어떤 경로로도
  원문 PII가 새지 않는다(`agent.py:285`).
- **Agentic Loop**: 최대 6회 왕복(무한루프 방지), `stop_reason != "tool_use"`가 정상 출구.
  도구 실패는 `_safe_tool_call`이 흡수해 `is_error=True`인 `tool_result`로 Claude에
  되먹임 → 모델이 인자를 고치거나 다른 도구로 재시도. MCP 도구 자체도
  `{"error", "available": [...]}` 형태의 **명시적 에러 계약**을 반환해 자가 정정 재료를
  준다(`ra/tasks.py:64,89`).
- **Abstention(기권)**: `SCORE_FLOOR=0.19 AND COVERAGE_FLOOR=0.28` — OR면 과회피라 AND.
  문턱값은 감이 아니라 범위내/범위밖 데이터셋의 경계 분포를 실측해 마진 중앙으로
  보정했고, 리랭커가 바뀔 때마다 재보정한 이력이 상수 주석에 축적(`agent.py:51-52`
  위 주석 블록).
  커버리지는 **확장 질의** 기준 — 검색은 동의어로 답을 찾는데 회피 판정만 원 질의로
  보면 자기모순.
- **오프라인 폴백**: 규칙 라우터가 5개 intent 분류. AE 트리아지는 케이스 마커 AND
  증상 마커 둘 다 있어야 발동 — "중대한 이상사례는 며칠 안에 보고?" 같은 규정 질문은
  검색으로 남긴다. 답변은 생성이 아니라 **근거 발췌**만(260자 스니펫), 질문을 본문에
  재인쇄하지 않아 사용자 전제가 검증 대상이 되는 것을 막는다.
- **PydanticAI 병렬 백엔드**: `AGENT_BACKEND=pydantic_ai` 전환. `MCPToolset`에 direct
  백엔드와 **같은 헬퍼 `_mcp_client()`로 만든 클라이언트를 전달** — URL과 인증 토큰이
  호출 시점의 config에서 나와 두 백엔드가 항상 같은 MCP 서버에 붙고, 도구 스키마
  출처가 동일해 이중 유지가 없다. `SYSTEM_PROMPT`·`_finalize` 검증 게이트·증거 북키핑
  헬퍼를 전부 direct와 공유해 "같은 계약, 다른 루프"를 실증(`pydantic_agent.py:135-140`).
- **MCP 서버**: "도구의 이름·docstring·타입힌트가 곧 LLM에게 주는 사용설명서 — FDE의
  실력은 여기서 드러난다"(`server.py:18-19`). PV 도구는 판정 후 `search_regulations`를
  중첩 호출해 근거 규정을 `basis`로 부착.
- **MCP 서버 인증(공개 원격 연결)**: `MCP_AUTH_TOKEN`이 설정된 경우에만
  `StaticTokenVerifier`로 Bearer 검증기를 조립(`server.py:_build_auth`) — 내부 네트워크
  전용(compose 내부·로컬)은 토큰 없이 무인증, 공개 URL 배포에서만 인증을 켠다.
  `/health` custom route는 인증 밖에 남겨 플랫폼 헬스체크가 무토큰으로 호출 가능.
  클라이언트 쪽은 `_mcp_client()`가 토큰을 Bearer 헤더로 자동 부착해 에이전트·preflight
  가 같은 경로로 인증한다.
- **웹 UI**: 모드 배지·grounded 배지·PII 마스킹 건수·검증 축별 경고·MCP 도구 트레이스·
  출처(버전·시행일 포함)를 전부 노출 — "신뢰를 UI로 보여주는" 설계.

### 3.3 PV 워크플로 (`src/pv/`)

- **트리아지 = 판단이 아니라 '대조'**: REG-005 §2의 중대성 기준 6개(사망·생명위협·입원/
  연장·장애·선천 기형·기타 중요)를 닫힌 목록으로 코드화, 규정 원문과 dict 키가 1:1
  일치(`triage.py:36-61`). 기한은 즉시(사망·생명위협, 0일) / 15일(그 외 중대) /
  정기보고(비중대) 3분기, **역일(calendar day)** 명시.
- **과탐 보수의 양방향 설계**: 사망은 미탐이 치명적이라 완곡어(별세·소천·영면…)까지
  열거로 넓히고, 반대로 '급사'가 "지급사유"에, '장애'가 "수면장애"(disorder≠disability)에
  오발화하는 동음이의는 활용형·결합형으로 좁힌다(`triage.py:27-58`). "recall과 precision을
  축마다 다르게 정한 근거를 말할 수 있다"가 포인트.
- **인과성 = 판정이 아니라 '제안+되물을 질문'**: WHO-UMC 6범주의 5범주 근사(Conditional
  제외). 출력 구조 자체가 `suggested + signals + rationale + missing_info`
  (`causality.py:118-123`). 정보 없는 요소는 충족으로 치지 않아 등급은 아래로만 보수 적용.
  NLP 디테일: "호전되지 **않았다**"를 반증으로 매핑하는 부정 어미 일반 규칙(긍정 어휘
  직후 6자 내 부정 어미) + 절 경계 + 용언 줄바꿈 랩 처리(`causality.py:35-63`).
- **코딩 3계층**: ①확정(검수 소사전, 자동 확정) ②후보(LLT 참조, `needs_confirmation=True`
  하드코딩 — 자동 확정 금지) ③미코딩(감지만). 확정과 후보를 **별도 dataclass로 분리해
  타입 수준에서 집계 오염 차단**(`coding.py:157-161`). 다의어 "발작"은 1계층에서 2계층으로
  강등 — "자동 확정 계층의 오탐은 시그널 집계를 오염시키므로 무관용".
- **ICSR 초안**: ICH E2D 4요소(환자·보고자·의심약·이상사례) 검증이 핵심. **마스킹과의
  긴장 해소**가 하이라이트 — 마스킹은 값을 지우지만 존재 신호("[이름]님", "45세 남성")는
  남으므로 마스킹된 텍스트 위에서 요건 판정(`report.py:13-17`). ④요소는 코딩 성공이
  아니라 '증상 서술 존재'로 판정해 코딩 실패가 '보고 불가' 오판으로 연쇄되는 것 차단.
- **PII 리댁터**: 주민번호·전화·이메일·차트번호·이름 5종. `\b` 대신 숫자 룩어라운드를
  쓰는 이유 — 한글도 `\w`라 "주민번호는…입니다"처럼 조사 직결 시 `\b`가 성립하지 않아
  매칭이 통째로 빠진다(`redactor.py:23-28`). 이름은 v9에서 설계 반전: 호칭 뒤 조사를
  허용 집합으로 여는 대신 무엇이든 매칭 + 스톱리스트로 오탐 방어 — "마스킹은 과탐이
  미탐보다 싸다". NFKC 폴딩으로 전각 숫자("０１０") 우회도 봉합.

### 3.4 검증 게이트 · preflight · 운영 (`src/verify/`, `src/preflight.py`, `src/observability.py`)

- **검증 게이트 축 구조**: 경고 5축(미확인 수치·방향 충돌·날짜 역할 충돌·전제 확인·
  폐지본 인용) + 비차단 라벨 1축(케이스 유래). `ok`는 손으로 나열하지 않고
  `BLOCKING_AXES`에서 **파생**(`verifier.py:344`), 관측성 계기판도 같은 정본 튜플을
  import — 새 축을 추가하면 계기판·자가 테스트에 자동 반영되고, 빠뜨리면 메타테스트가
  잡는다. v9에서 실제로 겪은 "검증기에만 축 추가하고 계기판에서 조용히 빠진" 회귀의 봉합.
- **대조 집합**: '검색 근거 ∪ 결정론적 도구 출력 − 입력 에코'를 strict 계층으로,
  케이스 서술은 별도 계층(from_case 라벨)으로 분리. **query와 as_of 에코를 모두 제거**
  — 하나만 빼면 사용자가 틀린 값을 전제로 물었을 때 맞장구가 검증을 통과하는 구멍.
  에러 응답은 통째 배제(에러 문구에 입력이 에코되므로).
- **단위 엄격성**: '근무일'≠'일', 고유어 수사(보름=15일)는 환산이 아니라 동치 표기만
  등재, '하루'는 "하루빨리" 오탐으로 의도적 제외(`verifier.py:150-151`). "수집되지 않는
  클레임은 통과처럼 보인다"는 사각지대 인식이 코드 주석에 명시.
- **검증기의 검증**: 메타모픽 변조 9축(교차문서 치환·오프셋·방향 뒤집기·고유어 치환·
  날짜 시프트·역할 스왑·부분날짜 역할 스왑·하이픈 범위 위조·부분날짜 시프트) 탐지율 +
  오탐 감시 4축 통과율. 탐지율은 '핀'(회귀 고정)이고 진짜 실측은 오프라인 실응답 전수
  E2EPassRate — 지표의 역할까지 구분.
- **preflight 4그룹 + 롤 분리**: ①설정 불변식(overlap<size 같은 파라미터 조합 모순 +
  **공개 배포 인증 가드** — `MCP_REQUIRE_AUTH=1`인데 토큰이 비면 '무인증 공개 서버'
  라는 조용한 보안 결함이므로 기동 거부) ②코퍼스 무결성(폐지 체인 다단 순회·순환 검출,
  **미래 시행일 문서가 시행 중 구판 없이 단독이면 결함** — 주제가 검색에서 조용히
  사라지는 형태) ③업무 데이터(마감일 전건 과거 = 부패 감지) ④스모크 canary +
  **게이트·마스킹 자가 테스트 27건**(축마다 planted/clean 쌍). 실패 1건이면 exit 1로
  기동 차단. 2-프로세스 배포에 맞춰 `--role mcp`(코퍼스·스모크) / `--role api`(자기
  데이터 + **MCP 서버 실연결을 60초까지 대기해 도구 6종 노출 확인**)로 게이트가
  분리되어 컨테이너별 기동 순서를 preflight가 흡수한다(`preflight.py:513`).
- **관측성**: `warn_rate`와 별도로 `warn_rate_checked`(클레임 있던 응답만 분모) — 범위밖
  질문 비중이 늘면 품질 변화 없이 경고율이 내려가는 **트래픽 믹스 착시** 방지.
  `Trace.total_ms`는 하위 span 합산이 아니라 최상위 wall-clock — "합산하면 같은 시간을
  두 번 세어 2배 지연 보고, 관측이 틀리면 없는 것보다 나쁘다". 감사 로그는 답변 원문이
  아니라 판정 요약만(PII 없음).
- **테스트·CI**: 불변식 테스트 7성질(결정론, 닫힌 출력 집합 `deadline_days ∈ {0,15,None}`,
  마스킹 멱등성 `redact(redact(x))==redact(x)`, PII 비유출, 코딩 계층 무교집합, 검증기
  자기일관성) + **고정 시드** fuzz 60건("무작위성은 입력 다양성용, CI 재현성 유지").
  CI는 preflight를 테스트보다 **먼저** 게이트로 실행 후 pytest → 평가 4종.

### 3.5 배포 (`render.yaml`, `docker-compose.yml`, `DEPLOY.md`)

- **2-프로세스 완전 분리 배포**: MCP 서버(RAG 인덱스·도구 실행 소유, 8001)와
  FastAPI(챗 UI·API, 8000)를 별도 서비스로 올리고, API는 `MCP_SERVER_URL`(streamable
  HTTP)로만 도구를 호출한다. 로컬 `./run.sh`도 배포와 동일하게 MCP 서버 기동 →
  헬스체크 대기 → API 기동 순서 — **로컬과 프로덕션이 같은 토폴로지**라 "로컬에선
  됐는데"가 구조적으로 없다.
- **한 레포에서 두 서비스가 뜨는 방식 — 레포 분리 대신 롤 분리**: MCP 서버(`src/mcp_server/`)와
  API(`src/api/`)는 별도 프로젝트가 아니라 **같은 패키지의 진입점 2개**다. Render는 루트
  `render.yaml` Blueprint 하나가 서비스 2개를 선언하는데, 둘 다 `rootDir: project`로 같은
  코드를 빌드하고 `startCommand`만 다르다 — rapv-mcp는 `python -m src.mcp_server.server
  --transport http`, rapv-assistant는 `uvicorn src.api.main:app`. Docker Compose도 같은
  이미지(`build: ./project`, Dockerfile 1개) 컨테이너 2개에 `command`만 다르게 주는 구조
  (Dockerfile 기본 CMD가 api 롤, mcp 롤은 command 오버라이드). 롤별 기동 게이트는
  `preflight --role mcp|api`가 담당한다. 효과: main 푸시 한 번에 두 서비스가 함께
  재배포되어 **코드·도구 스키마·데이터 버전이 서비스 간에 어긋날 수 없고**(`data/`도
  같은 이미지에 구워짐), 계약 테스트 한 벌이 두 서비스를 동시에 커버한다.
- **왜 서버리스가 아니라 Render인가**: '오래 살아야만 성립하는 상태'를 메모리에 들고
  있는 앱이라 서버리스(Vercel·Lambda류)의 실행 모델과 구조적으로 안 맞는다. 근거 3가지 —
  ①**부팅 시 1회 RAG 인덱싱**: 코퍼스 13종의 벡터+BM25 인덱스를 메모리에 구축
  (compose healthcheck가 '인덱스 완료 후 /health 200' + `start_period: 60s`인 이유).
  서버리스는 콜드스타트마다 이걸 다시 해서 첫 요청이 매번 수십 초짜리가 된다 —
  한 번 비싸게 만들어 오래 재사용하는 자산은 장수 프로세스가 맞다.
  ②**인메모리 계기판**: `warn_rate`·`warn_rate_checked`를 프로세스 메모리에 누적 —
  요청마다 인스턴스가 바뀌고 수시로 리셋되는 서버리스에선 카운터가 조용히 0으로
  초기화되거나 인스턴스별로 쪼개져 계기판이 거짓말을 한다(외부 Redis로 빼는 건 데모
  규모에 과잉 인프라). ③**MCP 서버 자체가 장수 프로세스**: streamable HTTP 상시
  연결을 받는 구조라 요청 단위로 뜨고 죽는 모델과 궁합이 안 맞는다.
  → 그래서 영속 프로세스 호스트(Render·Railway·Fly). 어필 포인트는 기술보다 태도 —
  "그냥 Render 썼다"가 아니라 **호스팅 선택도 실행 모델 이해에서 나온 아키텍처
  결정**으로 말한다.
- **Render 2-서비스 Blueprint**(`render.yaml`): rapv-mcp(web, Bearer 인증) +
  rapv-assistant(web). MCP 주소는 `fromService(property: host)` 자동 주입 + 고정 포트
  8001 조합 — `hostport` 속성은 '열린 포트 감지' 뒤에야 채워져 첫 sync에 빈 값이 될
  수 있어 일부러 안 썼다(플랫폼 동작까지 실측한 디테일). 서비스 간 통신은 rapv-mcp가
  공개여도 내부 네트워크 주소를 유지한다.
- **공개 MCP 서버의 보안 = fail-closed 2중**: ①토큰이 있어야 인증기가 조립되고
  ②`MCP_REQUIRE_AUTH=1` 가드가 preflight에서 '토큰 없는 공개 서버' 상태의 기동 자체를
  거부 — 나중에 토큰이 실수로 지워져도 **무인증 공개 상태로 조용히 돌아가지 않는다**.
  외부 클라이언트(Claude Desktop)는 커넥터 UI가 정적 Bearer를 지원하지 않아
  `mcp-remote` 프록시를 stdio로 끼워 연결한다(DEPLOY.md에 설정 예시).
- **stateless HTTP 전환 — 재배포 무중단 (실장애 → 수정 서사)**: streamable HTTP 의
  기본값은 상태 유지 세션이라 서버 재배포가 인메모리 세션 테이블을 비운다 — 세션을
  들고 있던 외부 클라이언트(Claude Desktop 의 mcp-remote)가 `Session not found` 404 로
  죽고 클라이언트 재시작 전까지 복구되지 않는 것을 **프록시 로그로 실측**했다(서버
  로그엔 아무것도 안 찍힌 게 오히려 단서 — 세션 계층에서 튕기면 애플리케이션까지 안
  온다). 1st-party 경로(에이전트·API·preflight)는 요청마다 새 연결이라 이 결함이
  구조적으로 관측 불가였고, 외부 클라이언트가 재배포를 넘겨 세션을 들고 있던 첫날
  드러났다. 이 서버는 서버발 기능(sampling·elicitation·알림·구독)을 쓰지 않는 순수
  요청-응답이라 세션의 이점이 없음을 확인하고 `stateless_http=True` 로 전환(테스트
  하니스도 동일 구성 — 세션 모드가 다르면 결함이 테스트에서 안 보인다). 재배포 직후
  **Desktop 재시작 없이** 프롬프트 호출 성공으로 프로덕션 실증. 말하기 포인트 2개:
  ① **상태의 층 구분** — 앱 수준 상태(RAG 인덱스·계기판)는 유지(Render 선택 근거),
  프로토콜 세션만 제거(재배포 무중단 근거). "stateless 라면서 왜 상태ful 호스팅?"
  꼬리질문의 답. ② **"기본값은 결정이 아니다"** — 결함이 관측된 순간 비로소 기본값이
  결정 대상이 된다.
- **Docker Compose 경로**: 같은 이미지(`project/Dockerfile`)로 mcp·api 두 컨테이너.
  mcp는 `expose`만 써서 호스트에 포트를 열지 않고(내부 전용), api는
  `depends_on: condition: service_healthy`로 **RAG 인덱스 구축 완료 후에만 기동** —
  healthcheck가 `/health` 200(인덱스 준비 완료 신호)을 본다. slim 이미지에 curl이
  없어 python urllib로 체크하는 것까지 실측 대응.
- **비용·운영 판단**: 공개 URL은 **오프라인 모드로 배포**(방문자가 API 비용을 태우는
  것 방지), LLM 모드는 면접 라이브 시연 직전에 web 서비스에만 키를 임시 주입 →
  시연 후 제거. "데모 하나에도 비용 경계를 설계했다"가 어필 포인트.

## 5. 면접관이 물어보게 만드는 미끼 (숨은 디테일 카드)

한 번에 다 말하지 말고, 대화 흐름에 맞춰 하나씩 꺼낸다.

1. **"한글은 `\b`가 안 통합니다"** — 한글도 `\w`라 조사 직결 시 단어 경계가 성립하지 않아,
   PII 정규식과 날짜 추출 모두 룩어라운드로 재설계. "수집 안 되는 클레임은 통과처럼
   보인다"는 사각지대 논리로 연결하면 신뢰성 설계 전체를 풀 수 있는 실마리.
2. **"폐지본을 무조건 빼면 틀립니다"** — 과거 시점(as_of) 조회에선 당시 시행 중이던
   구판이 정답. `[시행일, 후속본 시행일)` 구간 판정 + preflight의 폐지 체인 다단 순회가
   같은 규약을 공유. 버전 인지 검색의 깊이를 보여주는 카드.
3. **"경고 면제도 문서 단위로 좁혔습니다"** — 이력 검색을 했다고 전역으로 폐지본 경고를
   끄면 같은 턴의 현행 검색까지 면제된다. 실제 반환된 doc_id 집합으로만 면제 —
   "안전장치를 끄는 범위는 근거가 성립하는 단위로".
4. **"signed hashing 버그"** — 부호를 마지막 토큰이 덮어써 토큰 순서에 따라 코사인이
   -1이 되던 것을 누적으로 교정. 임베딩 재현성 디버깅 경험담으로 강력.
5. **"라우터와 코딩 사전의 어휘 통일"** — 오프라인 라우터가 PV 코딩 사전
   `symptom_keywords()`를 재사용해 "사전은 아는데 라우팅은 모르는" 어휘 불일치를
   구조적으로 제거. 사전 추가 = 라우팅 자동 확장.
6. **"검증 축의 정본 앵커"** — `ok`를 BLOCKING_AXES에서 파생하고 계기판이 같은 튜플을
   import. "가장 개연성 높은 부분 변경(검증기에만 축 추가)"이 조용히 반쪽 배포되는 걸
   구조로 막았다 — 실제 v9 회귀에서 배운 것.
7. **"관측이 틀리면 없는 것보다 나쁩니다"** — span 합산 2배 지연 버그,
   warn_rate_checked의 믹스 착시 방지, flow 로그의 파일:라인 자동 추출(수동 기재는
   코드 수정 시 거짓말). 운영 감각을 보여주는 3종 세트.
8. **"토큰이 지워져도 무인증으로 안 돌아갑니다"** — 공개 MCP 서버의
   `MCP_REQUIRE_AUTH` 가드. 인증은 토큰이 있으면 켜지는 구조라, 가드가 없으면 운영
   중 토큰이 실수로 삭제됐을 때 무인증 공개 서버로 **조용히 강등**된다. 이 상태를
   preflight 설정 불변식('값 각각은 유효한 조합 모순')으로 잡아 기동을 거부 —
   코퍼스 무결성 검사와 같은 fail-closed 계열이라는 일관성까지 말할 수 있다.

## 6. 말하기 전략 메모

- **3장·5장을 전부 말하려 하지 말 것.** 2장(2~3분)까지가 기본 발화량이고, 3장은
  꼬리질문이 왔을 때 해당 카드만, 5장은 대화가 깊어질 때 하나씩.
- 수치를 말할 때는 반드시 한계(개발셋/홀드아웃 구분, Wilson CI)를 같이 말한다 —
  정직성이 곧 차별화. "1.000은 완벽이 아니라 이 표본에서 실패 관측 0."
- 설계 결정마다 **"실패 사례 → 수정"의 서사**로 말한다(v8 signed hashing, v9 이름
  마스킹 반전, v9 축 정본화, v10 from_question 한정). "처음부터 잘 만든 척"보다
  "깨진 걸 어떻게 찾고 고쳤나"가 FDE답다.
- 시연 기회가 있으면 `./run.sh` 원커맨드(배포와 동일한 2-프로세스 기동) + 오프라인
  모드(키 없이 동작) + UI의 검증 배지·도구 트레이스를 강조. **공개 배포 URL이 있으면
  링크로 바로 시연**하고, Claude Desktop이 공개 MCP 서버에 원격으로 붙는 장면은
  "모델↔도구 분리"를 말로 하는 것보다 강력하다. `/health` 계기판(MCP 연결 상태 포함)
  도 보여줄 수 있으면 운영 감각 어필.
- **Claude Desktop 3-primitive 시연 각본** — 주도권 차이가 화면 세 장면으로 증명된다:
  1. 채팅에 "검색 가능한 규제문서 목록 보여줘" → Claude가 **스스로**
     `list_regulation_documents` 도구를 호출 — **Tool = model-controlled**
  2. 목록에서 doc_id 확인 후, **내가** + 메뉴(커넥터 → RAPV-Remote에서 추가)에서
     `REG-005` 리소스를 첨부 — **Resource = user/application-controlled**
     (코퍼스 13종을 구체 URI 정적 리소스로 등록해 메뉴에 열거된다)
  3. "이 문서 기준으로 중대 이상사례 보고 절차를 표로 정리해줘" → 첨부된 전문을
     근거로 답변
  4. `pv_case_intake` 프롬프트로 SOP 실행 — **Prompt = user-controlled**.
     케이스 입력 예시(한 줄): `환자 김민준님(45세 남성, 연락처 010-1234-5678)이
     A정 복용 후 30분 만에 아나필락시스가 발생해 응급실을 거쳐 입원했습니다. 투여
     중단 후 증상은 호전되었고 병용약물은 없습니다.` — 신호 설계: 호칭 붙은
     이름·전화(마스킹 시연), 복용 후(시간 선후), 입원(중대성→15일), 중단 후
     호전(dechallenge), 병용약물 없음(대체 원인 배제). 삽입된 프롬프트에서
     `[이름]님`·`[전화번호]` 확인 = Prompt primitive에도 적용된 심층방어 시연.
  마무리 멘트: "도구는 모델이 판단해서, 리소스는 사용자가 골라서, 프롬프트는
  사용자가 절차를 내려서 씁니다 — MCP 3대 primitive의 주도권 차이입니다."
- **평가 라이브 시연** — 2.5(평가와 정직성)를 말로만 하지 말고 그 자리에서 실행:
  ```bash
  cd project && .venv/bin/python -m eval.evaluate   # CI의 검색 품질 평가와 같은 명령
  ```
  출력 한 화면에 개발셋 `1.000 [0.893, 1.000] (n=32)` · 하드네거티브
  `1.000 [0.785, 1.000] (n=14)` · 홀드아웃 `1.000 [0.610, 1.000] (n=6)`이 **Wilson
  구간 병기**로 찍히고, "1.000은 '완벽'이 아니라 '이 표본에서 실패 관측 0'"이라는
  문장을 **리포트 자신이 인쇄**한다 — 정직성 규율이 사람 다짐이 아니라 출력물에
  박혀 있다는 증거. 같은 만점인데 n에 따라 구간이 다른 것(32 vs 6)을 손가락으로
  짚으면 "구간 폭 = 증거의 양" 설명이 화면 하나로 끝난다. 덤으로 임베더 비교표
  (tfidf/hashing/dense)까지 찍혀 "임베딩 뭘 쓰나" 방어도 같은 화면에 있다.
